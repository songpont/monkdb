# etl/input — วางไฟล์ข้อมูลดิบที่นี่

โฟลเดอร์นี้ถูก **gitignore ทั้งหมด** (ยกเว้นไฟล์ `.gitkeep` กับ `README.md` นี้)
ไฟล์ที่วางในนี้จะไม่ถูก commit ขึ้น git — ปลอดภัยสำหรับข้อมูลสุขภาพรายบุคคล

## วางไฟล์อะไร

วางไฟล์ export จาก HISO / ฐานทะเบียนพระสงฆ์ ได้เลย เช่น:

- `monks.csv` — ทะเบียนพระภิกษุสามเณร (1 แถว = 1 รูป)
- `diagnoses.csv` — การวินิจฉัยโรค (long format: monk_id, icd_code, ... หรือ wide format 30 คอลัมน์)
- `mortality.csv` — การมรณภาพรายปี (ถ้ามีแยก)
- หรือไฟล์เดียวรวมทุกอย่างก็ได้

รองรับ: `.csv`, `.tsv`, `.xlsx`, `.json`, `.jsonl`, `.parquet`, `.sqlite`

## ระบุมาด้วย (พิมพ์ในแชท หรือทำไฟล์ `_notes.md` ในโฟลเดอร์นี้)

1. **แต่ละไฟล์คืออะไร** + คอลัมน์สำคัญมีอะไรบ้าง (ชื่อคอลัมน์ + ความหมาย + ชนิดข้อมูล)
2. **คอลัมน์ไหนเป็น PII / อ่อนไหว** — ชื่อ, เลขบัตร, ชื่อวัดเต็ม, พิกัด ฯลฯ
   → ค่าเริ่มต้นคือ ETL จะ **ตัด/แฮชคอลัมน์เหล่านี้ทิ้ง** ก่อนขึ้น D1
3. **ระดับข้อมูลที่อยากได้บน D1**: raw รายรูป หรือ aggregate (จังหวัด×โรค×ช่วงอายุ)
4. คีย์เชื่อมระหว่างไฟล์ (เช่น `monk_id`)
5. ปีข้อมูล / วันที่ dump

## หลังวางไฟล์แล้ว

บอกผมได้เลยว่า "ไฟล์อยู่ใน etl/input แล้ว" — ผมจะ:
- สำรวจ schema จริงจากไฟล์
- ร่าง `migrations/0001_*.sql` (schema D1) + สคริปต์ ETL ใน `etl/`
- ทำ pipeline: `input/ -> transform -> etl/output/*.sql -> wrangler d1`
- เสนอ policy การตัด PII ให้ยืนยันก่อนรันจริง
